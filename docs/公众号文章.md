# 涨停 9 家那天，我清仓了

> 一个反直觉的数字：情绪分数崩掉的时候，涨停家数还好好的。

---

先看三个数字，全部来自一个 120 个交易日的实验市场。

**第 25 天**，情绪分 11（满分 13），仓位建议 25%/90%，五档里最高那档。当天涨停 4 家。

**第 37 天**，情绪分 3。两天前还是 11 分。当天涨停 6 家。

**第 40 天**，退潮确认。同一天出现两个天地板。

涨停 6 家，按很多人的标准叫「情绪还行」。但分数已经告诉你：能赚的钱赚完了，接下来是还钱的时候。

这不是玄学，是一套写成了代码的规则。为了让每个数字都能被检查，我用一个**合成的 120 天市场**做实验——固定随机种子，脚本开源，你可以逐日复现上面每一行。真实盘面不配合做对照实验，合成数据可以。

---

## 一、为什么「数涨停」不够

每个做短线的人都听过一句话：**看涨停家数**。

它有用，但它只衡量**宽度**。而决定明天能不能接力的，是**质量**——三件涨停家数看不见的事：

1. **梯队有没有高度**：有没有 3 只以上走到 4 板？没有高度，说明资金只敢做首板套利，不敢接力。
2. **高位股炸不炸**：昨天封住的 3 板、4 板，今天有多少炸开？炸板率是分歧最直接的计分器。
3. **昨天的板今天晋不晋级**：昨日涨停股今天还封着的比例。这是资金愿不愿意接昨天的货。

第 37 天就是典型：宽度还在（6 家涨停），质量已经归零——高位梯队全断，4 板以上一只不剩。所以分数从 11 掉到 3，而家数还在。

**先死的是质量，后死的是宽度。** 等家数掉下来，价格已经跌完了。

---

## 二、把情绪拆成三层

这套系统每天只回答一个问题：

> 当前市场的投机情绪，是在扩散、维持，还是在收缩？收缩有没有被**两天的证据**确认？

它不预测指数。它把盘面归类成一种状态，再把状态映射成仓位上限。

```
股票池 ──► 日线（不复权）──► 逐股判定 ──► 行业聚合
                                            │
                    ┌───────────────────────┘
                    ▼
        L1 全局  0-10    指数压力 · 跌停/涨停比 · 高位大面家数
        L2 主线  0-13    梯队 · 炸板率 · 晋级率 · 大面惩罚
        L3 龙头  三态    龙头断板天数 · 天地板家数
                    │
                    ▼
              双日退潮确认 ──► 动态止损 ──► 仓位档位
```

### L1：整个市场还能不能做

从 10 分开始扣：

- 沪深 300 跌超 2.5%，扣 4 分，并直接标记**系统性风险**（无条件空仓）；
- 跌停数 / 涨停数 大于 1.2，**且昨天也大于 1.2**，扣 3 分；
- 全市场高位大面（近 20 日至少 5 个涨停、当天从高点回吐 8% 以上）8 家扣 1 分，15 家扣 3 分。

注意第二条的「且昨天也大于」。单日跌停潮可能只是一只票带崩了一个板块，连续两日才说明风险在扩散。

第 53 天，指数跌 3%、跌停数远超涨停数、并且是连续第二天——L1 从 10 掉到 3，系统直接给 0 档。

### L2：主线还完整吗

只评估主线行业内部，四个分量相加，上限 13：

- **梯队**：主线里 4 板以上 ≥3 只给 4 分，≥1 只给 2 分，否则 0；
- **炸板率**：低于自己近 20 日的均值给 4 分，高出不超过 15% 给 2 分，否则 0；
- **晋级率**：不低于自己近 20 日均值给 2 分，低不超过 20% 给 1 分，否则 0；
- **大面惩罚**：全市场 0 家大面给 3 分，1–5 家给 1 分，6 家以上且有天地板倒扣 1 分。

11 分对应最高仓位档，8 分四档，5 分三档，2 分两档，2 分以下空仓。

### L3：龙头还封得住吗

主线里连板数最高、且没炸板的那只。它连续两天没封住，或者出现两个天地板，L3 就从 `none` 走到 `warning`，再到 `confirm`。

### 退潮：必须两天

```
退潮确认 = 今日 L2 ≤ 6 且 昨日 L2 ≤ 7 且 L3 为 warning/confirm
```

单日大面叫分歧，分歧之后可能是修复。连续两天情绪低、并且龙头确认走弱，才叫退潮。

## 三、最反直觉的一条设计：比「偏离」，不比「绝对值」

炸板率 40%，是好还是坏？

**取决于这个市场平时是多少。**

如果一轮行情里高位股天然有 40% 会炸，那 40% 就是它的正常值，不该扣分。所以 L2 的两个关键分量比的不是绝对值，而是**当日值与自己近 20 日均值的偏离**。

这里有个容易踩的顺序问题：当日值必须**先和旧基线比较，再写进序列**。如果先入队再算均值，当日值就把自己的基线拉过去了——序列越短，自反馈越强，分数会被越推越高。

还有一个小样本保护。高位股（3 板以上）少于 2 只时，炸板率直接按中性 2 分处理。理由很实在：一只都没有的时候，「炸板率 0%」不是好消息，是**没有样本**。

这条保护是后来补的，因为原始代码在这里犯了一个很贵的错——见下一节。

## 四、写代码时最痛的三个坑

这套东西最初是一个能跑通的 notebook，三个版本都在仓库的 `legacy/` 里原样保留。把它重写成可测试的库时，挖出了八个 bug。

挑三个最致命的，因为它们的共同点是：**输出看起来全都正常**。

### 坑一：炸板股的连板数永远是 0

原代码这么数连板：

```python
if self.is_break_up(latest):
    result['board_num'] = self.count_consecutive_boards(df, len(df) - 1)
```

而 `count_consecutive_boards` 从最后一根 K 线往回数，遇到非涨停就停。炸板的那根**收盘不是涨停**，所以：

**每一个炸板股，连板数都是 0。**

后果是连锁的。炸板率只统计「3 板以上且炸板」的股票：

```python
high_board = [s for s in main_hl if s.get('board_num', 0) >= 3 and s.get('is_break')]
```

这个集合恒为空 → 炸板率恒为 0 → 低于 0.3 的基线 → **这个分量永远拿满分 4 分**。

于是无论市场多差，L2 都被垫高 4 分。系统看起来每天都能给出分，其实每天都在偏乐观。

修复很简单：数的是**今天尝试的板数**，不是今天封住的板数。

```python
return count_consecutive_boards(history) + 1   # 昨日连板 + 今日这一次尝试
```

### 坑二：最高仓位档，数学上不可达

```python
if L2_score >= 16:      # 25% / 90% / 五档
```

但 L2 是 `min(13, ...)`，**上限就是 13**。`>= 16` 永远为假。

结果是所有高分日都塌缩到四档（20%/70%），五档从来没有出现过。写代码的人不会发现，因为他看到的是一个合理的 20%；交易的人也不会发现，因为他看到的是「今天给了四档」。

**参数的取值范围和判据阈值对不上，是最隐蔽的一类 bug——它不报错，只是永远走不到那个分支。**

修复后按真实尺度切分：11 / 8 / 5 / 2。

### 坑三：没有龙头的时候，每天都是 warning

断板天数这样算：

```python
new_break_days = 0 if leader in sealed_codes else break_days + 1
```

冰点期，主线里一只封板的都没有，`leader` 是 `None`，`None in sealed_codes` 为 `False`，于是**断板天数每天 +1**。

跑够两天，L3 就是 `confirm`，配合冰点期本来就低的 L2，**双日退潮每天都被触发**。一个应该在退潮前报警的模块，变成了一个永远在报警的模块。

修复：没有龙头不是「龙头断板」，是「还没有龙头」。L3 返回 `none`，天数清零。

### 另外五个

- 主线惯性：字段写成 `{'name': ...}`，读的时候取 `['sector_name']`，拿到的永远是 `None`，**惯性逻辑从未生效**；
- 炸板率、晋级率序列：前两版**从头到尾没有 append 过**，基线永远是默认的 0.3；
- 单只涨停就被当成主线：冰点期 L2 打出 7 分，给了三档仓位；
- `10.95 / 10 - 1` 在双精度下等于 `0.09499…`，正好封在涨停价的股票被判成「没涨停」；
- 多线程共享一个统计缓存，注释写着「需要加锁」，代码里没有锁。

八个坑，每一条都有以它命名的回归测试，比如 `test_break_up_board_number_is_not_zero`、`test_no_leader_is_not_a_warning`、`test_l2_is_capped_and_tier_reachable`。

**这大概是这个仓库最值得看的部分**：不是那套评分多聪明，而是它怎么被拆开、逐条证伪、再装回去。

## 五、它不懂什么

写这类东西最容易犯的错，是把工具说得太神。几条必须讲：

1. **没有回测，也没有参数验证。** 所有阈值来自交易经验，不是拟合出来的。仓库里没有收益曲线，也**不构成任何投资建议**。把它接到下单接口就是灾难。
2. **涨跌幅统一按 10% 判。** 创业板、科创板 20%，ST 5%，北交所 30%，目前全会误判——这是文档里列的第一改进项，因为它直接影响「涨停家数」这个最基础的分母。
3. **行业分类落后于热点。** 申万二级更新慢，新概念会被拆到旧行业里，主线可能识别不到。
4. **没有竞价数据。** 9:15–9:25 的竞价溢价是日内最早的情绪信号，目前只输出，不参与打分。
5. **它不是因子。** 输出是离散状态，不能直接丢进多因子模型做截面回归。

规则系统的价值不是「更准」，是**可争论**。你可以指着 11 分说「这个梯队分给高了」，然后去改 `main_hl` 的过滤条件。黑箱做不到这件事。

## 六、怎么用

仓库：**github.com/314405571-star/a-share-sentiment-cycle**

```bash
pip install -r requirements.txt

# 离线：合成 120 天市场，不需要联网，复现本文所有数字
python examples/demo_sentiment_cycle.py

# 测试
python tests/test_indicators.py
python tests/test_sentiment.py
```

接实盘（baostock 免费、免注册）：

```bash
python -m src.scanner --build-pool stock_pool.csv        # 全市场股票池
python -m src.scanner --pool stock_pool.csv --date 2026-11-10
```

作为库调用：

```python
from src.sentiment import Config, EmotionEngine, State

engine = EmotionEngine(Config(), State.load("emotion_state.json"))
snap = engine.update("2026-11-10", signals, hs300_return=-0.004)

snap.l1, snap.l2, snap.l3      # 10.0, 9.0, 'none'
snap.main_sector               # 主线（带惯性）
snap.position_tier             # 'T4'
print(snap.report())           # 日报
```

`State` 必须落盘。昨日涨停股、炸板率基线、龙头、断板天数，全在里面——**丢掉状态，等于丢掉模型的一半。**

文档在 `docs/算法总结.md`：公式、参数表、复杂度、八个坑的完整复盘、八条局限、七个改进方向。

## 最后

市场不缺预测涨跌的声音，缺的是对「**现在是什么状态**」的诚实判断。

第 25 天给五档，第 37 天给两档，第 40 天确认退潮，第 53 天强制空仓。中间没有任何一次「我觉得要涨了」。

这套系统最值钱的地方，可能不是它在第 37 天说了什么，而是它**允许自己说不知道**——冰点期没有主线，L2 就是 0；没有龙头，L3 就是 none；没有样本，炸板率就不参与评分。

不让模型在没信息的时候硬给一个分数，比让它给对更重要。
